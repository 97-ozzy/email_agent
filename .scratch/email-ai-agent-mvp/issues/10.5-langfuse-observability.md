## Privacy

- [x] Default `include_content=False` and `include_binary_content=False`. No full prompts, tool arguments/results, email text, chunks, attachments, sensitive filter values or raw exception messages in exported telemetry.
- [x] Apply the same privacy policy to custom spans, events, status descriptions, final answers, identifiers and automatic instrumentation. Sanitize failures using safe codes/types.
- [x] Explicit local content-debugging opt-in is separate from enabling tracing; it permits textual prompts, answers and tool payloads, but never credentials, tokens, binary content or raw exception messages.
- [x] Use stable pseudonymous user/document identifiers without exporting their original values or pseudonymization secrets.

## Agreed decisions

1. Scope: trace chat turns and operations nested beneath them; independent commands, including `/sync_new`, `/sync_old`, `/search` and reindex, remain outside this ticket. Business spans without an active traced turn must not create orphan root traces.
2. Content opt-in: permit textual prompts, answers and tool payloads only after `LANGFUSE_CAPTURE_CONTENT=true`; keep binary capture disabled and credentials, tokens and raw exception messages excluded in every mode.
3. Outcome precedence: `error` for propagated ChatError; `limit_exceeded` for a limit-triggered fallback or exhausted tool budget; `partial` for other degraded source coverage; otherwise `successful`. Keep separate safe flags for simultaneous limit and Gmail degradation.
4. Partial coverage: when the existing answer warns about Gmail unavailability, mark the turn `partial` even if the agent did not attempt a Gmail search, unless the higher-priority error/limit outcome applies. Do not change existing answer behavior to implement this classification.
5. Identifiers: use a locally persisted random user UUID, a new session UUID per ChatSession instance and a new turn UUID per ask. `/clear` retains the session ID. Never derive user identity from the email address. Document where the local identity is stored and how to reset it.

## Comments

Compatibility research: installed and locked PydanticAI is 1.107.10. The privacy fix is available since 1.107.6; constrain the lower bound accordingly and regression-test exports. See [upstream advisory](https://github.com/pydantic/pydantic-ai/security/advisories/GHSA-4x9p-g9wm-8q7f). Settings is a frozen dataclass, not Pydantic Settings. Prefer per-Agent `InstrumentationSettings(tracer_provider=..., include_content=False, include_binary_content=False)` over global instrumentation. Langfuse SDK v4 should be paired with a compatible self-hosted server; [SDK overview](https://langfuse.com/docs/observability/sdk/overview) distinguishes v4 from newer SDK/server combinations. Reverify at implementation time.

FoodTech review: its tracing module exports explicit inputs/outputs and needs privacy adaptation; do not copy those writes. Disable automatic exception recording in custom stages and export only sanitized error codes. Tool failures already converted to return values require explicit failure markers. Gmail MCP subprocess internals need not be instrumented: observe the existing client boundary while retaining the in-process context.
